# University Shortlisting Tool — Database Schema
**Version:** 1.0  
**Status:** Proposed logical schema and data dictionary aligned to the project implementation plan.  
**Database:** PostgreSQL; SQLAlchemy models and Alembic migrations.  
**Audience:** Parth (database/data pipeline), Harsh (backend), product coordinator, QA, AI coding agents.

## 1. Purpose and design principles
This document defines the logical relational model for the University Shortlisting Tool. It is a detailed baseline, not permission to invent source facts. Parth owns implementation and migrations; Harsh reviews whether the schema supports API/domain rules; the product coordinator reviews feature coverage.

### 1.1 Non-negotiable invariants
1. University identity and program identity are separate entities.
2. A program's intake, requirements, deadlines and fees can vary by intake/year and must not be flattened into one timeless value.
3. Every critical external fact must be traceable to evidence/source, retrieval time, applicable period and verification state.
4. Source candidates, reviewed/published facts and historical versions must be distinguishable.
5. AI extraction is a proposal, not truth. Human or explicitly approved validation policy governs publication.
6. Missing data is not zero, false, eligible or a fabricated estimate.
7. Student profiles and private activity must be isolated by user ownership.
8. Recommendation runs must be reproducible from stored inputs, rule/scoring version and data snapshot references.
9. Money always includes currency and period/basis. Original source amounts must be preserved when conversions are calculated.
10. Schema changes are made through Alembic migrations, not manual production edits or production `create_all`.
11. Ingestion is idempotent; repeated imports must not create duplicate logical records.
12. Store only personal data needed for the product. Private uploads require explicit purpose, access controls and deletion/retention policy.

## 2. Naming and type conventions
- Table names: plural `snake_case`.
- Column names: `snake_case`.
- Primary keys: UUID (`uuid`); generated by application/database consistently.
- Foreign keys: `{referenced_entity}_id`.
- Timestamps: `timestamptz` in UTC.
- Date-only fields: `date`.
- Money: `numeric(14,2)` plus currency code and period/basis. Do not use floating point for money.
- Confidence/score: numeric with documented scale and provenance; do not present raw extraction confidence as truth.
- Flexible source payloads may use `jsonb`, but stable queryable domain fields must remain typed columns.
- Enumerations may use PostgreSQL enums or checked text values. Pick one convention and manage changes with Alembic.
- Add `created_at`, `updated_at` to mutable business tables; use explicit history tables for material fact changes.
- Use indexes for foreign keys, common filters, status, country/field, and date fields; add full-text/trigram indexes only after query needs are confirmed.
- Do not use `NULL` to mean multiple different things without a documented meaning. Missingness/status fields should explain why a value is absent.

## 4. Table specifications

### 4.1 `users`
Purpose: account identity and role-safe account status.
- `id UUID PK`
- `email CITEXT or normalized VARCHAR(320) UNIQUE NOT NULL`
- `password_hash VARCHAR NULL` (only if local password authentication is used; never plaintext)
- `display_name VARCHAR(120) NULL`
- `status VARCHAR NOT NULL` — `active`, `pending_verification`, `suspended`, `deletion_pending`, `deleted`
- `email_verified_at TIMESTAMPTZ NULL`
- `last_login_at TIMESTAMPTZ NULL`
- `created_at`, `updated_at TIMESTAMPTZ NOT NULL`
- `deleted_at TIMESTAMPTZ NULL`
Indexes/constraints: unique normalized email; status index.
Notes: roles may be represented in a separate `user_roles` table if multi-role support is required; do not accept role from user-controlled payloads.

### 4.2 `roles` and `user_roles` (recommended)
`roles`: `id UUID PK`, `key UNIQUE` (`student`, `reviewer`, `admin`), `description`, timestamps.  
`user_roles`: `user_id FK`, `role_id FK`, `assigned_by_user_id FK NULL`, `assigned_at`, composite PK (`user_id`,`role_id`).  
Worker identity should use service credentials, not a normal student's role.

### 4.3 `student_profiles`
Purpose: applicant's current editable profile; separate from program catalogue.
- `id UUID PK`
- `user_id UUID FK users UNIQUE NOT NULL` (one primary profile per user in MVP)
- `intended_degree_level VARCHAR NOT NULL`
- `field_id UUID FK fields NULL` or controlled `field_key`
- `preferred_country_codes JSONB or normalized child table` (prefer child table if ordered multi-country preferences are queried)
- `academic_degree VARCHAR NULL`
- `academic_major VARCHAR NULL`
- `institution_name VARCHAR NULL`
- `grade_value NUMERIC(8,3) NULL`
- `grade_scale_min NUMERIC(8,3) NULL`
- `grade_scale_max NUMERIC(8,3) NULL`
- `grade_system VARCHAR NULL` (CGPA, percentage, GPA, other; use normalized enum)
- `graduation_status VARCHAR NULL`
- `graduation_year SMALLINT NULL`
- `backlog_count INTEGER NULL`
- `english_test_status VARCHAR NULL` (not_taken, booked, completed, waived, unknown)
- `english_test_type VARCHAR NULL`
- `english_test_overall NUMERIC(5,2) NULL`
- `english_test_component_scores JSONB NULL`
- `other_test_scores JSONB NULL`
- `work_experience_months INTEGER NULL`
- `projects_summary TEXT NULL` (avoid unnecessary personal details)
- `career_goal VARCHAR NULL`
- `budget_amount NUMERIC(14,2) NULL`
- `budget_currency CHAR(3) NULL`
- `budget_basis VARCHAR NULL` (annual/full_degree; tuition_only/all_in must be explicit)
- `target_intake_year SMALLINT NULL`
- `target_intake_term VARCHAR NULL`
- `profile_completed_at TIMESTAMPTZ NULL`
- `created_at`, `updated_at`
Constraints: nonnegative budget/backlogs/experience; grade range must align with scale where provided; budget amount requires currency and basis; graduation year must be plausible but avoid overly restrictive assumptions.
Privacy: private to owner; avoid logging profile payloads.

### 4.4 `profile_country_preferences` (preferred normalized option)
- `profile_id FK student_profiles`
- `country_code CHAR(2) FK countries.code`
- `preference_rank SMALLINT NOT NULL`
- `is_mandatory BOOLEAN NOT NULL DEFAULT false`
- composite PK (`profile_id`,`country_code`); unique (`profile_id`,`preference_rank`)
Use this instead of JSON if country preferences need filtering/ranking.

### 4.5 `profile_priorities`
- `id UUID PK`
- `profile_id FK student_profiles`
- `priority_key VARCHAR NOT NULL` (cost, academic_fit, career, quality, destination, scholarship, etc.)
- `weight NUMERIC(5,4) NOT NULL`
- `created_at`, `updated_at`
Constraint: weights nonnegative; normalized weights/version policy documented. User preference weights are distinct from global model weights.

### 4.6 `countries`
- `code CHAR(2) PK` (ISO alpha-2)
- `name VARCHAR(120) UNIQUE NOT NULL`
- `region VARCHAR NULL`
- `official_study_url TEXT NULL`
- `official_immigration_url TEXT NULL`
- `created_at`, `updated_at`
Only seed country identity/official URLs from validated sources. Country-specific rules should be versioned as facts/resources, not frozen in these columns alone.

### 4.7 `cities`
- `id UUID PK`
- `country_code CHAR(2) FK countries`
- `name VARCHAR(160) NOT NULL`
- `slug VARCHAR(180) NOT NULL`
- `admin_region VARCHAR NULL`
- `created_at`, `updated_at`
Unique: (`country_code`,`slug`); index country/name.

### 4.8 `fields`
- `id UUID PK`
- `key VARCHAR UNIQUE NOT NULL`
- `display_name VARCHAR NOT NULL`
- `parent_field_id UUID FK fields NULL`
- `description TEXT NULL`
- `is_active BOOLEAN NOT NULL DEFAULT true`
- timestamps
Use controlled field taxonomy and map source-specific labels to canonical fields. Do not create a new field for every text variant without normalization.

### 4.9 `universities`
Purpose: institution identity; does not itself represent a degree program.
- `id UUID PK`
- `canonical_name VARCHAR NOT NULL`
- `slug VARCHAR UNIQUE NOT NULL`
- `country_code CHAR(2) FK countries NOT NULL`
- `official_website_url TEXT NULL`
- `institution_type VARCHAR NULL`
- `recognition_status VARCHAR NOT NULL DEFAULT 'unknown'` (`recognized`, `not_recognized`, `under_review`, `unknown`)
- `external_identifiers JSONB NULL` (only identifiers whose use is permitted; keep named fields if heavily queried)
- `created_at`, `updated_at`
- `published_at TIMESTAMPTZ NULL`
Unique/indexes: country + normalized name; external identifier where unique and available. Do not use fuzzy name as the sole permanent identity key.
Notes: recognition is evidence-backed and date-sensitive; it must not be a free-form unsupported claim.

### 4.10 `campuses`
- `id UUID PK`
- `university_id FK universities NOT NULL`
- `name VARCHAR NULL`
- `city_id UUID FK cities NULL`
- `address_public TEXT NULL`
- `latitude NUMERIC(9,6) NULL`, `longitude NUMERIC(9,6) NULL` only if needed and from permitted sources
- `created_at`, `updated_at`
Coordinates are optional; do not collect precise personal locations.

### 4.11 `programs`
Purpose: normalized degree-program identity.
- `id UUID PK`
- `university_id UUID FK universities NOT NULL`
- `campus_id UUID FK campuses NULL`
- `canonical_name VARCHAR NOT NULL`
- `slug VARCHAR NOT NULL`
- `degree_level VARCHAR NOT NULL` (masters and more specific types where needed)
- `field_id UUID FK fields NULL`
- `description TEXT NULL`
- `official_program_url TEXT NULL`
- `delivery_language VARCHAR NULL`
- `study_mode VARCHAR NULL` (full_time, part_time, online, blended, unknown)
- `duration_min_months SMALLINT NULL`
- `duration_max_months SMALLINT NULL`
- `is_active BOOLEAN NOT NULL DEFAULT true`
- `publication_status VARCHAR NOT NULL DEFAULT 'candidate'` (`candidate`, `published`, `hidden`, `retired`)
- `created_at`, `updated_at`, `published_at TIMESTAMPTZ NULL`
Unique: university + normalized program name + degree level/campus where appropriate. Do not merge distinct programs solely because names look similar.

### 4.12 `program_intakes`
Purpose: intake-specific information and deadline applicability.
- `id UUID PK`
- `program_id FK programs NOT NULL`
- `intake_year SMALLINT NOT NULL`
- `intake_term VARCHAR NOT NULL` (fall/spring/winter/summer/other)
- `application_open_date DATE NULL`
- `application_deadline DATE NULL`
- `start_date DATE NULL`
- `is_open_for_applications BOOLEAN NULL`
- `status VARCHAR NOT NULL` (`candidate`, `verified`, `closed`, `unknown`)
- `created_at`, `updated_at`
Unique: (`program_id`,`intake_year`,`intake_term`). A deadline is not valid without its intake/year context and evidence.

### 4.13 `admission_requirements`
Purpose: structured requirements for a program or intake.
- `id UUID PK`
- `program_id FK programs NOT NULL`
- `program_intake_id UUID FK program_intakes NULL`
- `requirement_type VARCHAR NOT NULL` (degree, major, grade, language_test, standardized_test, prerequisite_course, work_experience, document, other)
- `requirement_key VARCHAR NOT NULL`
- `operator VARCHAR NOT NULL` (gte, gt, eq, in, contains, completed_course, any_of, all_of, manual_review)
- `expected_value JSONB NOT NULL`
- `is_mandatory BOOLEAN NOT NULL DEFAULT true`
- `group_key VARCHAR NULL` and `group_operator VARCHAR NULL` (`AND`/`OR`) to represent logical groupings
- `applicability_notes TEXT NULL`
- `source_fact_id UUID FK fact_records NULL`
- `created_at`, `updated_at`
Requirements must support nested ANY/ALL logic as the rules engine requires. JSON is for structured typed values, not unvalidated prose-only requirements. Preserve original wording in evidence/source records. Requirement evaluation results are stored separately per run.

### 4.14 `program_fees`
Purpose: program-specific fee facts, with effective/applicable periods.
- `id UUID PK`
- `program_id UUID FK programs NOT NULL`
- `program_intake_id UUID FK program_intakes NULL`
- `fee_type VARCHAR NOT NULL` (tuition, mandatory_fee, application_fee, deposit, insurance, other)
- `amount NUMERIC(14,2) NULL`
- `currency CHAR(3) NULL`
- `period VARCHAR NULL` (one_time, semester, academic_year, full_program, month, other)
- `academic_year VARCHAR NULL`
- `student_category VARCHAR NULL` (international/domestic/other if supported)
- `is_mandatory BOOLEAN NULL`
- `status VARCHAR NOT NULL` (`verified`, `estimated`, `unverified`, `stale`, `conflicted`, `unavailable`)
- `fact_id UUID FK fact_records NULL`
- `created_at`, `updated_at`
Rule: amount missing means unknown/unavailable, never zero. Currency and period required for any published numeric amount.

### 4.15 `sources`
Purpose: registry of external data sources and permitted use.
- `id UUID PK`
- `name VARCHAR NOT NULL`
- `base_url TEXT NOT NULL`
- `source_type VARCHAR NOT NULL` (official_university, government, regulator, statistical, licensed_aggregator, other)
- `authority_tier SMALLINT NOT NULL`
- `owner_or_publisher VARCHAR NULL`
- `allowed_use_policy VARCHAR NOT NULL` (manual_reference, permitted_fetch, licensed_api, public_dataset, prohibited_automated_fetch, review_required)
- `terms_url TEXT NULL`
- `robots_policy_checked_at TIMESTAMPTZ NULL`
- `rate_limit_notes TEXT NULL`
- `license_notes TEXT NULL`
- `refresh_interval_hours INTEGER NULL`
- `enabled BOOLEAN NOT NULL DEFAULT false`
- `created_at`, `updated_at`
Only enable automated fetch when terms/access/license policy has been reviewed. Aggregators can aid discovery, but official sources should be preferred for program facts unless use rights and data quality are established.

### 4.16 `source_documents`
Purpose: retrieval record/snapshot metadata for a source page/document.
- `id UUID PK`
- `source_id FK sources NOT NULL`
- `canonical_url TEXT NOT NULL`
- `title TEXT NULL`
- `document_type VARCHAR NULL`
- `content_hash CHAR(64) NULL`
- `retrieved_at TIMESTAMPTZ NOT NULL`
- `http_status SMALLINT NULL`
- `storage_uri TEXT NULL` (private object storage if permitted)
- `content_excerpt TEXT NULL` (small evidence excerpt; respect copyright and source policy)
- `parser_version VARCHAR NULL`
- `fetch_status VARCHAR NOT NULL`
- `created_at`
Unique/dedupe using source + canonical URL + content hash/retrieval policy. Do not store full copyrighted pages unless permitted.

### 4.17 `fact_records`
Purpose: stable identity for a specific field/fact about an entity.
- `id UUID PK`
- `entity_type VARCHAR NOT NULL` (university, program, intake, fee, requirement, scholarship, city, outcome, country_rule, other)
- `entity_id UUID NOT NULL` (polymorphic link; enforce through service validation or use entity-specific link tables)
- `fact_key VARCHAR NOT NULL` (e.g. tuition_amount, minimum_english_score, deadline)
- `applicability_key VARCHAR NULL` (intake/year/student category)
- `current_version_id UUID NULL` (FK fact_versions added after table creation or deferred constraint)
- `current_status VARCHAR NOT NULL` (`candidate`, `in_review`, `verified`, `estimated`, `unverified`, `stale`, `conflicted`, `unavailable`, `superseded`, `rejected`)
- `created_at`, `updated_at`
Unique logical identity: entity type + entity ID + fact key + applicability key, subject to PostgreSQL null-uniqueness strategy.
Critical facts should not be represented only as untraceable columns; domain tables can have convenient current-value columns but must link to evidence/version records.

### 4.18 `fact_versions`
Purpose: immutable history of proposed/approved fact values.
- `id UUID PK`
- `fact_record_id FK fact_records NOT NULL`
- `version_number INTEGER NOT NULL`
- `value_json JSONB NULL`
- `normalized_value_json JSONB NULL`
- `status VARCHAR NOT NULL`
- `effective_from DATE NULL`
- `effective_to DATE NULL`
- `applicable_intake_year SMALLINT NULL`
- `applicable_intake_term VARCHAR NULL`
- `extraction_method VARCHAR NULL` (manual, parser, AI_assisted, licensed_api, dataset)
- `extraction_confidence NUMERIC(5,4) NULL` (candidate signal only; not truth)
- `reviewed_by_user_id UUID FK users NULL`
- `reviewed_at TIMESTAMPTZ NULL`
- `review_reason TEXT NULL`
- `created_by_user_id UUID FK users NULL`
- `created_at TIMESTAMPTZ NOT NULL`
Unique: (`fact_record_id`,`version_number`). Published/current facts must link to evidence. Keep prior versions immutable; create a new version for corrections.

### 4.19 `fact_evidence`
Purpose: many-to-many evidence connecting fact versions to source documents.
- `id UUID PK`
- `fact_version_id FK fact_versions NOT NULL`
- `source_document_id FK source_documents NOT NULL`
- `evidence_excerpt TEXT NULL`
- `evidence_locator TEXT NULL` (section, heading, page or structured API path)
- `supports_or_conflicts VARCHAR NOT NULL` (`supports`, `conflicts`, `context`)
- `reviewer_note TEXT NULL`
- `created_at`
One fact version can have multiple evidence records. Conflicts should remain visible until resolved; do not erase conflicting sources.

### 4.20 `fact_review_events`
- `id UUID PK`
- `fact_record_id FK fact_records NOT NULL`
- `fact_version_id FK fact_versions NULL`
- `reviewer_user_id FK users NOT NULL`
- `action VARCHAR NOT NULL` (`approve`, `reject`, `request_evidence`, `mark_stale`, `resolve_conflict`, `reopen`)
- `reason TEXT NOT NULL` for rejection/override/high-impact decisions
- `created_at TIMESTAMPTZ NOT NULL`
Append-only audit-style history.

### 4.21 `ingestion_jobs` and `ingestion_job_items`
`ingestion_jobs`:
- `id UUID PK`
- `source_id FK sources NULL`
- `job_type VARCHAR NOT NULL` (discover, fetch, parse, normalize, validate, refresh)
- `status VARCHAR NOT NULL` (queued, running, succeeded, partial, failed, cancelled)
- `started_at`, `finished_at TIMESTAMPTZ NULL`
- `records_seen INTEGER NOT NULL DEFAULT 0`
- `records_created INTEGER NOT NULL DEFAULT 0`
- `records_updated INTEGER NOT NULL DEFAULT 0`
- `records_rejected INTEGER NOT NULL DEFAULT 0`
- `error_summary TEXT NULL` (sanitized)
- `worker_version VARCHAR NULL`
- `created_by_user_id FK users NULL`
- `created_at`
`ingestion_job_items`:
- `id UUID PK`
- `job_id FK ingestion_jobs NOT NULL`
- `source_document_id FK source_documents NULL`
- `entity_type VARCHAR NULL`
- `external_key VARCHAR NULL`
- `status VARCHAR NOT NULL`
- `candidate_payload JSONB NULL`
- `validation_errors JSONB NULL`
- `fact_record_id FK fact_records NULL`
- `created_at`, `updated_at`
Unique/idempotency key should prevent the same source record from being inserted repeatedly. Raw candidate payloads must be minimized and must not contain private student data.

### 4.22 `recommendation_rulesets`
- `id UUID PK`
- `version VARCHAR UNIQUE NOT NULL`
- `description TEXT NOT NULL`
- `eligibility_config JSONB NOT NULL`
- `scoring_config JSONB NOT NULL`
- `is_active BOOLEAN NOT NULL DEFAULT false`
- `created_by_user_id FK users NULL`
- `created_at`
- `activated_at TIMESTAMPTZ NULL`
Only one active ruleset per environment unless deliberate multi-version experimentation is designed. Ruleset changes require tests and a change record.

### 4.23 `recommendation_runs`
- `id UUID PK`
- `user_id FK users NOT NULL`
- `profile_id FK student_profiles NOT NULL`
- `profile_snapshot JSONB NOT NULL` or immutable profile-version reference
- `ruleset_id FK recommendation_rulesets NOT NULL`
- `data_snapshot_at TIMESTAMPTZ NOT NULL`
- `status VARCHAR NOT NULL` (queued, running, succeeded, partial, failed)
- `started_at`, `completed_at TIMESTAMPTZ NULL`
- `input_hash CHAR(64) NULL`
- `result_summary JSONB NULL`
- `warning_summary JSONB NULL`
- `created_at`
A run is immutable after completion; re-run creates a new run. Snapshot references must make the result reproducible enough to explain the result later.

### 4.24 `recommendation_items`
- `id UUID PK`
- `run_id FK recommendation_runs NOT NULL`
- `program_id FK programs NOT NULL`
- `tier VARCHAR NULL` (`ambitious`, `target`, `safer_fit`; null if excluded/not tiered)
- `eligibility_status VARCHAR NOT NULL` (eligible, conditionally_eligible, ineligible, unknown_needs_review)
- `fit_score NUMERIC(7,4) NULL`
- `score_breakdown JSONB NULL`
- `reason_codes JSONB NOT NULL DEFAULT []`
- `concerns JSONB NOT NULL DEFAULT []`
- `missing_information JSONB NOT NULL DEFAULT []`
- `rank_in_tier INTEGER NULL`
- `created_at`
Unique (`run_id`,`program_id`). Store the explanation and enough rule outcome details to explain inclusion/exclusion. Never store fabricated admission probabilities.

### 4.25 `requirement_evaluations`
- `id UUID PK`
- `recommendation_item_id FK recommendation_items NOT NULL`
- `admission_requirement_id FK admission_requirements NOT NULL`
- `status VARCHAR NOT NULL` (pass, fail, conditional, unknown)
- `applicant_value_json JSONB NULL`
- `expected_value_json JSONB NOT NULL`
- `explanation TEXT NOT NULL`
- `evidence_fact_version_id FK fact_versions NULL`
- `created_at`
Unique (`recommendation_item_id`,`admission_requirement_id`). Mandatory unknown requirements must prevent a fully eligible status.

### 4.26 `saved_programs`
- `user_id FK users NOT NULL`
- `program_id FK programs NOT NULL`
- `note TEXT NULL`
- `created_at TIMESTAMPTZ NOT NULL`
Composite PK (`user_id`,`program_id`). User can save a program only once; idempotent save behavior should be documented.

### 4.27 `comparisons` and `comparison_items`
`comparisons`:
- `id UUID PK`
- `user_id FK users NOT NULL`
- `title VARCHAR(160) NULL`
- `created_at`, `updated_at`
`comparison_items`:
- `comparison_id FK comparisons NOT NULL`
- `program_id FK programs NOT NULL`
- `position SMALLINT NOT NULL`
- composite PK (`comparison_id`,`program_id`); unique (`comparison_id`,`position`).
Enforce the configured maximum program count in service validation.

### 4.28 `cost_scenarios` and `cost_scenario_items`
`cost_scenarios`:
- `id UUID PK`
- `user_id FK users NOT NULL`
- `program_id FK programs NULL`
- `name VARCHAR(160) NOT NULL`
- `currency CHAR(3) NOT NULL`
- `scenario_type VARCHAR NOT NULL` (low, base, high, custom)
- `assumptions JSONB NOT NULL`
- `total_amount NUMERIC(14,2) NULL`
- `funding_amount NUMERIC(14,2) NULL`
- `funding_gap NUMERIC(14,2) NULL`
- `calculation_version VARCHAR NOT NULL`
- timestamps
`cost_scenario_items`:
- `id UUID PK`
- `scenario_id FK cost_scenarios NOT NULL`
- `cost_type VARCHAR NOT NULL`
- `amount NUMERIC(14,2) NULL`
- `currency CHAR(3) NOT NULL`
- `period VARCHAR NOT NULL`
- `status VARCHAR NOT NULL` (verified, estimated, user_provided, unavailable)
- `fact_version_id FK fact_versions NULL`
- `assumption_note TEXT NULL`
- `created_at`
Keep published facts separate from user-entered assumptions; do not overwrite source values with scenario values.

### 4.29 `scholarships`
- `id UUID PK`
- `name VARCHAR NOT NULL`
- `provider_name VARCHAR NOT NULL`
- `official_url TEXT NULL`
- `country_code CHAR(2) FK countries NULL`
- `award_type VARCHAR NULL`
- `amount_min NUMERIC(14,2) NULL`
- `amount_max NUMERIC(14,2) NULL`
- `currency CHAR(3) NULL`
- `coverage_type VARCHAR NULL` (tuition, living, partial, full, fixed, other)
- `renewable BOOLEAN NULL`
- `status VARCHAR NOT NULL` (candidate, verified, stale, closed, unknown)
- `fact_id FK fact_records NULL`
- `created_at`, `updated_at`
Funding amounts must be evidence-backed and include currency/coverage. Do not imply an applicant will receive the award.

### 4.30 `scholarship_eligibility_rules`
- `id UUID PK`
- `scholarship_id FK scholarships NOT NULL`
- `rule_key VARCHAR NOT NULL`
- `operator VARCHAR NOT NULL`
- `expected_value JSONB NOT NULL`
- `is_mandatory BOOLEAN NOT NULL DEFAULT true`
- `group_key VARCHAR NULL`
- `source_fact_id FK fact_records NULL`
- timestamps
Represent eligibility conditions as structured rules where possible; retain original terms as evidence.

### 4.31 `scholarship_program_links`
- `scholarship_id FK scholarships NOT NULL`
- `program_id FK programs NOT NULL`
- `link_type VARCHAR NOT NULL` (university-wide, program-specific, external)
- `created_at`
Composite PK (`scholarship_id`,`program_id`).

### 4.32 `funding_opportunities`
Purpose: broader grants, government schemes, exams/fellowships or other funding opportunities beyond standard scholarships.
- `id UUID PK`
- `name VARCHAR NOT NULL`
- `provider_name VARCHAR NOT NULL`
- `opportunity_type VARCHAR NOT NULL`
- `official_url TEXT NULL`
- `eligible_countries JSONB NULL`
- `eligible_nationalities JSONB NULL`
- `study_levels JSONB NULL`
- `field_eligibility JSONB NULL`
- `award_summary TEXT NULL`
- `opening_date DATE NULL`
- `deadline DATE NULL`
- `status VARCHAR NOT NULL` (candidate, verified, open, closed, stale, unknown)
- `fact_id FK fact_records NULL`
- timestamps

### 4.33 `loan_scenarios`
- `id UUID PK`
- `user_id FK users NOT NULL`
- `name VARCHAR(160) NOT NULL`
- `principal_amount NUMERIC(14,2) NOT NULL`
- `currency CHAR(3) NOT NULL`
- `annual_interest_rate NUMERIC(7,5) NOT NULL`
- `tenure_months INTEGER NOT NULL`
- `moratorium_months INTEGER NOT NULL DEFAULT 0`
- `interest_during_moratorium VARCHAR NOT NULL`
- `repayment_method VARCHAR NOT NULL`

## 5. Constraints and indexes
Minimum:
- Unique normalized user email.
- Unique canonical country code, university slug, program identity key, program intake key, source URL/hash policy and fact version number.
- Foreign keys on all relationships; choose `ON DELETE` behavior explicitly.
- `CHECK` constraints for nonnegative costs, valid date order, positive page-independent domain values, rating bounds, score ranges and valid currencies where possible.
- Index foreign keys and common filters: country, field, degree level, program publication status, intake year/term, source status, fact status, job status, review queue status, user ownership and created timestamps.
- Add composite indexes based on real query patterns (e.g. published programs by country/field; intake by program/year/term; fact status by updated time).
- Full-text search can begin with PostgreSQL full-text search; add `pg_trgm` or vector search only if an approved use case justifies it.
- Avoid indexing every JSONB field; index stable high-use domain columns first.
- Use database-level constraints plus Pydantic validation; neither replaces the other.
- Use transactions for multi-table publish/review operations and recommendation-run persistence.

## 6. Data ingestion and verification model
1. Register source and document its authority, terms/licensing, allowed access method, rate limits and refresh policy.
2. Fetch only when permitted; store retrieval status, timestamp, canonical URL, content hash and parser version.
3. Extract candidate entities/facts using parsers or AI-assisted extraction.
4. Normalize field names, currencies, dates, country codes, intake labels and institution/program identity.
5. Validate required fields, value ranges, applicability, source compatibility and duplicate identity.
6. Create candidate fact versions and link supporting/conflicting evidence.
7. Send critical or uncertain changes to review queue.
8. Reviewer approves/rejects with reason; publish new version and preserve history.
9. Mark older facts stale when freshness policy expires; do not silently treat stale as current.
10. Monitor failures, parse drift, duplicate rate, conflicts, provenance coverage and review backlog.

Source hierarchy:
- Official university/program/admissions/fees pages for program facts.
- Government/regulator/official immigration pages for recognition and visa/work rules.
- Official scholarship provider pages for award eligibility and deadlines.
- Official statistical datasets or well-defined studies for outcomes/living-cost context.
- Aggregators are useful for discovery, but must not override official facts without a documented reason and permitted use.
- Check licensing, terms, access restrictions and rate limits before automated collection. Do not assume public visibility means unrestricted scraping rights.

Rules:

- Migration names explain the change.
- Test upgrade from empty database and upgrade from previous migration.
- Avoid destructive migrations without explicit approval, backup and data migration plan.

- Include a repeatable local test dataset and a way to reset only development/test data.
- Never commit real student personal data, secrets or licensed data that the project cannot redistribute.

## 8. Data retention and privacy
- Student profiles, saved programs, recommendation runs and financial scenarios are private.
- Uploads, if introduced, need a separate private object-storage metadata model, explicit consent/purpose, access policy, retention and deletion process. Do not store raw files as public database blobs by default.
- Define whether account deletion anonymizes historical audit records or deletes them, consistent with applicable obligations.
- Avoid sensitive values in logs, audit summaries and ingestion payloads.
- Use least-privilege database credentials for API, worker and migration jobs where practical.
- Backups must be access-controlled and restore-tested.

## 9. Required database tests
- Fresh migration to head and upgrade from prior revision.
- Unique constraints and foreign-key integrity.
- Ownership isolation for student-private tables.
- Idempotent imports and duplicate detection.
- Source/fact/evidence version linkage and conflict handling.
- Mandatory requirement with unknown evidence yields unknown, not eligible.
- Historical recommendation run remains stable after later fact edits.
- Money values preserve currency, period, source status and original amount.
- Cost scenarios reconcile totals and line items.
- Scholarship and deadline states correctly become stale/closed according to policy.
- Admin publish/reject creates immutable review/audit history.
- Deletion and retention behavior is tested.
- No synthetic fixture is marked as official verified data.

## 11. Open implementation decisions (must be recorded, not guessed)
- Final pilot countries, disciplines and intake coverage.
- Exact authentication/session provider and role assignment mechanism.
- Whether user reviews, uploads, user collections, notification preferences and account export/deletion ship in MVP.
- Exact source-use/license decisions and automated refresh frequency.
- Whether to use a polymorphic `fact_records.entity_id` pattern or entity-specific fact-link tables. Entity-specific links are more referentially safe; polymorphic links are simpler but need application-level validation.
- Whether currency conversion rates are stored in a dedicated `exchange_rates` table (recommended if conversions need historical reproducibility).
- Whether search requires `pg_trgm`, full-text search or embeddings; do not add pgvector solely by default without a defined retrieval need.
- Whether the background worker uses a lightweight scheduler first or a Redis-backed queue; match the agreed architecture and operational needs.
- Retention period for source snapshots, audit events, candidate payloads and private user data.

## 12. Definition of done
- All tables/relations have a documented owner and purpose.
- Alembic migrations create the schema reproducibly.
- Every critical published fact can be traced to source evidence, version, applicability and verification status.
- Student data is private and ownership tests pass.
- Program identity and intake-specific data are modelled separately.
- Recommendation runs preserve profile/rules/data references and explanations.
- Cost, scholarship, loan and outcome records preserve currency/period/scope/source.
- Ingestion can be re-run safely and never auto-promotes unsupported AI output to verified fact.
- The data dictionary and ERD match actual SQLAlchemy models and migrations.
